## Notes for the plans still to write

**Plan 3 — Abilities and MCP.**
- `wp_register_ability()` exists in core (confirmed on WP 7.0). Register the
  `pediment` category and the nine abilities from spec §3 on the Abilities API
  init hooks; take the exact hook names and the `meta.mcp.public` flag from the
  installed WordPress and `WordPress/mcp-adapter` docs at the time.
- MCP Adapter is a separate canonical plugin (bundling via Composer is
  deprecated since its v0.7.0) and is not yet on WordPress.org. Soft
  dependency: create the MCP server inside `mcp_adapter_init` only when
  `WP\MCP\Core\McpAdapter` exists. Pin one adapter release zip in `.wp-env.json`
  for CI.
- `get-vocabulary` wraps `Pediment\Design\Vocabulary::styles()` (Plan 2) and
  adds tokens, allowed blocks, rules, WP version and languages.
- `upsert-style` / `delete-style` wrap `Pediment\Design\SiteStyles` (Plan 2).
- Content rules: new `Pediment\Content\Policy`; the literal-value check reuses
  the token predicate from `StyleValidator` (extract it to a shared class
  rather than copying it).
- The `client-kit` validator (`validate-blocks`) is Node + `@wordpress/blocks` +
  `@wordpress/block-library` + jsdom, pinned per WordPress version; it must also
  register the site's style variations so `is-style-*` classes validate.
- Write `docs/mcp.md`, including the 2026-10-14 acceptance test.

**Plan 4 — Converter and v4.0.0.**
- Start by reading each legacy block's `render.php` and `style.scss` and the
  three client sites' usage (`pediment-website` uses 15 block types,
  `straight-solutions-website` 5, Workation 5). Choose each mapping, then add
  the plugin default styles the mappings need (likely `stat`, `tile`,
  `media-card`, `media-row`, `quote-card`) through Plan 2's mechanism.
- Every mapper fixture is validated in CI with the Plan 3 Node validator.
- Seeder: remove re-sync and content-arbitration updates (`ContentHash`, the
  update branches of `Differ`/`Applier`, related `Reporter` output); keep
  identity, languages, navigation, header part, media, claim and adopt.
- Release: a `feat!` commit already exists from Plan 1, so release-please cuts
  4.0.0. Ask Jonas before pushing or merging the release PR.

**Plan 5 — Site conversions.** Open one thread per client repo in
`/Users/jonas/Entwicklung/agent-channel` (see its README). Each client
workspace pins Pediment 4.0.0, runs `wp pediment convert --dry-run`, adds theme
styles where the theme had styled a legacy block, compares screenshots at 375,
768 and 1440 px, and Jonas reviews before production conversion through
wp-admin.

**Plan 6 — v5.0.0.** Gate: `check-page` reports zero legacy blocks on all three
production sites. Delete the 18 blocks (registration, `render.php`, styles,
editor code, PHPUnit block-render tests); keep the converter mappers until
v6.0.0.
